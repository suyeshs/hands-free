# Restaurant Client (Storefront)

Next.js-based customer-facing storefront for the Handsfree POS system, deployed as a Cloudflare Worker using OpenNext.

## Overview

This is the main customer-facing application where users:
- Browse the menu and place orders
- Enter delivery information
- Make payments
- Track order status

## Key Features

- **Multimodal Input**: Voice ordering support via integration with theme-edge-worker
- **OTP Verification Toggle**: Can enable/disable phone verification flow
- **Multi-tenant**: Supports multiple restaurant brands via theme presets
- **Real-time Updates**: WebSocket integration for order status updates
- **R2 Integration**: Direct image uploads for menu items

### OTP Verification Toggle

The `NEXT_PUBLIC_ENABLE_OTP_VERIFICATION` variable controls the phone verification flow:

- **`"false"`** (current): Users enter phone + name and proceed directly to address entry
  - No PIN entry screen
  - No MSG91 OTP verification
  - Mock verification via restaurant worker bypass endpoints

- **`"true"`**: Traditional OTP flow with PIN verification
  - User enters phone number
  - Receives OTP via SMS/WhatsApp
  - Enters PIN to verify
  - Proceeds to address entry

## Architecture

### Worker Structure

- **Main Entry**: `.open-next/worker.js` (generated by OpenNext)
- **Static Assets**: `.open-next/assets/` (served via Workers Assets binding)
- **Durable Objects**:
  - `DOQueueHandler`: Queue management
  - `DOShardedTagCache`: Distributed caching

### Integration Points

1. **Restaurant Worker** (`handsfree-restaurant.suyesh.workers.dev`)
   - Customer verification: `/api/customers/verify-device`
   - Phone lookup: `/api/customers/phone/:phone`
   - Address management: `/api/customers/:id/addresses`

2. **Theme Edge Worker** (`theme-edge-worker.suyesh.workers.dev`)
   - Theme customization
   - Menu data
   - Voice session management

3. **Orders Worker** (if separate)
   - Order creation and management
   - Payment processing

## Customer Order Flow

### Current Flow (OTP Disabled)

```
1. Customer Info Screen
   ├─ Enter phone number
   ├─ Enter name
   └─ Click Continue
      └─ Calls /api/customers/verify-device (mock bypass)
         └─ Returns mock customer object

2. Delivery Address Screen
   ├─ For new customers: Enter address
   └─ For returning customers: Select from saved addresses

3. Checkout Summary
   └─ Review order

4. Payment
   └─ Process payment

5. Confirmation
   └─ Show order confirmation
```

### Traditional Flow (OTP Enabled)

```
1. Customer Info Screen
   ├─ Enter phone number
   └─ Click Continue
      └─ Calls /api/customers/phone/:phone

2. PIN Entry Screen (PhoneOTPStep)
   ├─ Enter 6-digit PIN
   └─ Verify via MSG91
      └─ Calls /api/customers/verify-device

3. Name Entry (if new customer)
   └─ Enter name

4. Delivery Address Screen
   [... continues same as above]
```

## Troubleshooting

### Build Failures

If you see "Cannot find module 'next/package.json'":
```bash
cd /Users/stonepot-tech/projects/restaurant-pos-ai/workers/restaurant-client
npm install
npm run deploy:worker
```

### OTP Not Disabled

If users still see PIN entry screen:
1. Verify `NEXT_PUBLIC_ENABLE_OTP_VERIFICATION: "false"` in wrangler.jsonc
2. Rebuild and redeploy: `npm run deploy:worker`
3. Check browser console for environment variable value

### Customer Verification Errors

If verification fails:
1. Check restaurant worker logs: `wrangler tail handsfree-restaurant`
2. Verify mock endpoints are active (no MSG91_AUTH_KEY secret)
3. Check CORS headers in restaurant worker

## Maintenance

### Updating Next.js

```bash
npm update next react react-dom
npm run deploy:worker
```

### Changing Theme Preset

Edit `wrangler.jsonc`:
```json
"NEXT_PUBLIC_THEME_PRESET": "your-brand-name"
```

Then redeploy:
```bash
npm run deploy:worker
```

### Re-enabling OTP Verification

1. Edit `wrangler.jsonc`:
   ```json
   "NEXT_PUBLIC_ENABLE_OTP_VERIFICATION": "true"
   ```

2. Set MSG91_AUTH_KEY secret in restaurant worker:
   ```bash
   cd ../restaurant
   wrangler secret put MSG91_AUTH_KEY
   ```

3. Redeploy both workers:
   ```bash
   wrangler deploy  # From restaurant/
   cd ../restaurant-client
   npm run deploy:worker
   ```

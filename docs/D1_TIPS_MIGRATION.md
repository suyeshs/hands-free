# D1 Database Migration Guide - Tips Feature

This guide outlines all the changes needed to sync your Cloudflare D1 database with the new tips management feature.

## Overview

The tips feature adds a new table to track tips separately from sales transactions, along with endpoints to sync and query tips data from the POS system.

## 1. Database Schema Changes

### Run this SQL on your D1 database:

```sql
-- Tips Management Table
CREATE TABLE IF NOT EXISTS tips (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,

  -- Order/Invoice linkage
  invoice_number TEXT NOT NULL,
  order_number TEXT,
  table_number INTEGER,
  order_type TEXT NOT NULL,

  -- Tip details
  tip_amount REAL NOT NULL,

  -- Staff attribution (dual tracking: staff_id preferred, server_name fallback)
  staff_id TEXT,
  server_name TEXT,

  -- Entry metadata
  entered_by_staff_id TEXT,
  entered_by_name TEXT,
  entry_method TEXT NOT NULL DEFAULT 'manual',

  -- Timestamps
  created_at TEXT NOT NULL,
  tip_date TEXT NOT NULL,

  -- Cloud sync tracking
  synced_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Indexes for performance
CREATE INDEX IF NOT EXISTS idx_tips_tenant_date ON tips(tenant_id, tip_date);
CREATE INDEX IF NOT EXISTS idx_tips_invoice ON tips(invoice_number);
CREATE INDEX IF NOT EXISTS idx_tips_staff ON tips(staff_id);
CREATE INDEX IF NOT EXISTS idx_tips_server_name ON tips(server_name);
CREATE UNIQUE INDEX IF NOT EXISTS idx_tips_tenant_invoice ON tips(tenant_id, invoice_number);
```

### Using Wrangler CLI:

```bash
# Apply the migration
wrangler d1 execute <YOUR_DATABASE_NAME> --file=./docs/d1-tips-migration.sql

# Or run directly
wrangler d1 execute <YOUR_DATABASE_NAME> --command="CREATE TABLE IF NOT EXISTS tips ..."
```

## 2. Cloudflare Worker Updates

### A. Add Tips Endpoints

Add the following endpoints to your Cloudflare Worker (see `cloudflare-worker-sales-endpoints.ts`):

- `POST /api/tips/:tenantId/sync` - Sync tips from POS to D1
- `GET /api/tips/:tenantId/summary` - Get tips summary with staff breakdown
- `GET /api/tips/:tenantId/list` - Get all tips for date range

### B. Update Durable Object WebSocket Handler

Add the `tip_recorded` message handler to your Durable Object (see `durable-object-tips-handler.ts`):

```typescript
case 'tip_recorded': {
  const { tip } = message;
  await this.syncTipToD1(tip, env);
  this.broadcast(message, ws);
  break;
}
```

## 3. Data Flow

### POS → Cloud Sync Flow:

1. **Staff enters tip** on POS after bill printing
2. **Local SQLite** stores tip immediately
3. **WebSocket broadcast** sends `tip_recorded` event to Durable Object
4. **Durable Object** writes tip to D1 database
5. **D1 database** stores tip for reporting and cross-device access

### Cloud → POS Query Flow:

1. **Daily Sales Report** fetches tips summary from local SQLite
2. **Future enhancement**: Could fetch from D1 for cross-device reporting

## 4. Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `id` | TEXT | Unique tip ID (generated by POS) |
| `tenant_id` | TEXT | Restaurant/tenant identifier |
| `invoice_number` | TEXT | Links to sales_transactions.invoice_number |
| `order_number` | TEXT | Optional order number |
| `table_number` | INTEGER | Table number (for dine-in) |
| `order_type` | TEXT | dine-in, takeout, or delivery |
| `tip_amount` | REAL | Tip amount in currency |
| `staff_id` | TEXT | Staff user ID (if logged in) |
| `server_name` | TEXT | Server name (fallback if no staff_id) |
| `entered_by_staff_id` | TEXT | Who entered the tip |
| `entered_by_name` | TEXT | Name of who entered tip |
| `entry_method` | TEXT | manual or auto |
| `created_at` | TEXT | ISO 8601 timestamp |
| `tip_date` | TEXT | Date in YYYY-MM-DD for aggregation |
| `synced_at` | TEXT | Timestamp when synced to cloud |

## 5. Important Notes

### Data Separation
- Tips are stored **separately** from `sales_transactions` table
- `sales_transactions.grand_total` does **NOT** include tips
- Tips are **NOT** shown on customer receipts
- Tips are **NOT** included in cash register reconciliation

### Unique Constraint
- One tip per invoice (enforced by unique index)
- Prevents duplicate tips for same order
- POS checks for existing tips before showing modal

### Staff Attribution
- **Preferred**: `staff_id` (when server has logged in)
- **Fallback**: `server_name` (from table session)
- **Unassigned**: Both NULL (for takeout without server)

## 7. Rollback Plan

If you need to rollback:

```sql
-- Remove tips table
DROP TABLE IF EXISTS tips;

-- Remove indexes (if table still exists)
DROP INDEX IF EXISTS idx_tips_tenant_date;
DROP INDEX IF EXISTS idx_tips_invoice;
DROP INDEX IF EXISTS idx_tips_staff;
DROP INDEX IF EXISTS idx_tips_server_name;
DROP INDEX IF EXISTS idx_tips_tenant_invoice;
```
